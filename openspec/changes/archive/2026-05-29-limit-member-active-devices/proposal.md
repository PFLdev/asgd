## Why

当前会员账号允许在多台设备登录，但服务端缺少“同一时间最多 3 台设备使用会员功能”的准入控制。需要在不限制登录设备总数的前提下，为会员功能增加实时活跃设备数限制，降低账号共享和权益滥用风险。

## What Changes

- 新增会员功能活跃设备准入能力：同一账号最多 3 台设备可同时使用会员功能。
- 使用 Redis 维护账号维度的活跃设备租约集合，请求会员功能时原子判断、占用或刷新设备租约。
- 当前设备已占用名额时刷新租约并放行；未占用且活跃设备数少于 3 时新增租约并放行；超过限制时拒绝访问并返回可解释状态。
- 通过租约 TTL 自动释放崩溃、断网、未主动退出的设备占用。
- 记录关键准入事件，支持后续审计、排查和用户设备管理能力扩展。
- 不改变“允许一个账号登录多个设备”的登录策略。

## Capabilities

### New Capabilities
- `member-active-device-limit`: 定义会员功能活跃设备准入规则、租约生命周期、并发约束、拒绝行为和异常兜底。

### Modified Capabilities

无。

## Impact

- 会员功能入口需要接入统一的活跃设备限制校验，避免绕过。
- 认证上下文或请求参数需要稳定提供 `userId`、`deviceId`，最好包含 `sessionId` 便于排查和后续设备管理。
- 新增 Redis 依赖使用场景，需要 Lua 或等价原子操作保证并发下最多 3 台设备。
- 可能新增审计表或日志，记录设备占用、刷新、拒绝、过期、释放等事件。
- 需要补充 Service/Controller 测试，覆盖并发、续租、过期、超限、Redis 异常等场景。
